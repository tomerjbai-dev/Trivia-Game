> מקורות: `MILESTONES.md` (Milestone 5), `PRD.md` (Online-only, PWA, פרטיות, מחוץ להיקף), `ARCHITECTURE.md` (1 – סיכונים 3–4; 2.6 אבטחה ופרטיות; 2.7 PWA; 2.8 GitHub ו-Deployment; ADR-4, ADR-5), `CLAUDE.md` (פריסה, דחיפה, חשבונות).
> מצב בתחילת העבודה: Milestones 1–4 אושרו (✅). האפליקציה מלאה ועובדת מקומית: שלושה מסכים, יצירת שאלות דרך `POST /api/questions` (Node.js runtime, `maxDuration = 60`, `Cache-Control: no-store`), סינון תוכן, טיפול בשגיאות, Manifest ואייקונים (בלי Service Worker). ה-Repository `tomerjbai-dev/Trivia-Game` מחובר כ-`origin`. אין עדיין פרויקט Vercel.

## 1. גבולות ה-Milestone

**בתוך Milestone 5:**
- הכנה קטנה של הקוד לפריסה (גרסת Node.js קבועה), בלי שינוי בהתנהגות המוצר.
- הדרכה צעד אחר צעד של המשתמש: יצירת חשבון Vercel, ייבוא ה-Repository, הגדרת משתני סביבה ופריסה ראשונה.
- בדיקה מלאה של האתר החי (ידנית יחד עם המשתמש + בדיקות טכניות שלי מול הכתובת הציבורית).
- תיעוד הכתובת החיה ותהליך הפרסום/Rollback.

**לא בתוך Milestone 5:** דומיין מותאם אישית, Rate Limiting או תקרת תקציב (החלטת המשתמש, ARCHITECTURE 2.6), Analytics, Database/Migrations, Service Worker, CI נפרד (GitHub Actions), ענפי Feature/Preview workflow, שינויי עיצוב או התנהגות.

**מי עושה מה:**

- **Claude:** מכין את הקוד, מריץ את בדיקות האיכות, מבקש אישור ל-push, מדריך בכל צעד, בודק את האתר החי מבחוץ ומתעד.
- Claude **לא** מתקין את Vercel CLI, לא מריץ `vercel deploy` ולא נוגע בהגדרות החשבון — הפריסה נעשית רק דרך החיבור ל-GitHub (ARCHITECTURE 2.8).

## 2. הכנת הקוד לפריסה

### 2.1 גרסת Node.js (`package.json`)
- הוספת `"engines": { "node": "24.x" }` — אותה גרסה שרצה מקומית (Node 24), כדי ש-Vercel יבנה ויריץ על אותה גרסה ולא על ברירת מחדל שעלולה להשתנות.
- אין צורך ב-`vercel.json`: Vercel מזהה Next.js אוטומטית, ו-`maxDuration = 60` כבר מוגדר ב-`src/app/api/questions/route.ts` (בתוך המגבלה של תוכנית Hobby).

### 2.2 בדיקות לפני ה-push הראשון לפריסה
- `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:e2e`, `npm run build` — כולם חייבים לעבור.
- וידוא ש-`.env.local` ו-`.vercel/` מוחרגים ב-`.gitignore` (קיים) ושאין מפתח בקוד: חיפוש `sk-` ו-`OPENAI_API_KEY=` עם ערך בקבצים במעקב Git.
- וידוא שאין שימוש ב-`NEXT_PUBLIC_` עבור משתני OpenAI.

### 2.3 ה-push
- ה-Milestone דורש push כדי שהאתר יתעדכן. לפי CLAUDE.md — **לפני כל push עוצרים ומבקשים את אישור המשתמש**. ה-push הזה אינו מסמן את ה-Milestone כ-✅; הסימון ✅ ניתן רק בסוף, אחרי בדיקת המשתמש ("דחוף שינויים לגיטהאב" האחרון / אישור מפורש).
- הערה: ייתכן שהקוד ב-GitHub כבר עדכני (commit של Milestone 4). במקרה כזה Vercel יכול לפרוס את מה שכבר שם, ושינוי `engines` ייכנס ב-push שאחרי האישור.

## 3. הדרכת המשתמש בהקמת Vercel (צעד אחר צעד, בשפה פשוטה)

1. **הרשמה:** vercel.com ← Sign Up ← תוכנית **Hobby** (חינמית, לשימוש אישי/לימודי — ARCHITECTURE סיכון 3) ← "Continue with GitHub".
2. **ייבוא הפרויקט:** Add New… ← Project ← בחירת `Trivia-Game`. אם הוא לא מופיע: "Adjust GitHub App Permissions" ומתן גישה ל-Repository הזה בלבד.
3. **הגדרות הפרויקט במסך הייבוא:** Framework Preset = Next.js (אוטומטי); Root Directory = שורש; פקודות Build/Install — להשאיר ברירת מחדל. שם הפרויקט קובע את הכתובת (`<שם>.vercel.app`) — מומלץ שם באנגלית קצר, למשל `chachmologim`.
4. **משתני סביבה (Environment Variables)** — לפני לחיצה על Deploy:
   - `OPENAI_API_KEY` = המפתח (המשתמש מעתיק בעצמו מ-`.env.local` או מ-OpenAI; Claude לא קורא את הקובץ).
   - `OPENAI_MODEL` = `gpt-5`.
   - לסמן את הסביבות Production (ו-Preview לפי הרצון; לא חובה).
   - להזכיר: לא לסמן את המפתח כ-"Expose to browser" ולא להוסיף לו קידומת `NEXT_PUBLIC_`.
5. **Deploy** ← המתנה לסיום ה-Build (כ-1–2 דקות) ← קבלת הכתובת.
6. **בדיקת חיבור אוטומטי:** Settings ← Git — לוודא שה-Production Branch הוא `main`.
7. אם ה-Build נכשל — המשתמש מעתיק את הודעת השגיאה מ-"Build Logs", ו-Claude מתקן בקוד (בלי לגעת בהגדרות החשבון).

הערות להדרכה:
- Deployment Protection (Vercel Authentication) חל בברירת מחדל רק על Preview, לא על Production — לוודא שהכתובת הראשית נפתחת בחלון גלישה בסתר בלי התחברות.
- אם המשתמש משנה משתנה סביבה אחרי הפריסה — צריך "Redeploy" כדי שייכנס לתוקף.

## 4. בדיקות האתר החי

### 4.1 בדיקות טכניות שלי (מול הכתובת הציבורית, בלי מפתחות)
- **HTTPS:** הכתובת נפתחת ב-`https://`, ו-`http://` מפנה ל-HTTPS.
- **שלושת המסכים:** `/`, `/trivia`, `/about` מחזירים 200 ונטענים בדפדפן המובנה; ניווט תחתון עובד; בדיקה בגדלי טלפון, טאבלט ומחשב (resize).
- **API:** `POST /api/questions` עם נושא תקין מחזיר שאלה (קריאה אחת אמיתית, עולה מעט); כותרת `Cache-Control: no-store`; נושא ריק מחזיר `400 INVALID_TOPIC`; גוף גדול מדי נדחה.
- **אי-חשיפת המפתח:** חיפוש `sk-` ו-`OPENAI` בקובצי ה-JavaScript שהדפדפן מוריד (רשימת בקשות הרשת + תוכן הקבצים) — אסור שיימצא ערך; תגובות השגיאה מכילות רק `{ code }`.
- **PWA:** `/manifest.webmanifest` נטען עם השדות מ-ARCHITECTURE 2.7; האייקונים (`/icons/*.png`, `apple-touch-icon`) מחזירים 200; אין Service Worker רשום.
- **פרטיות:** אין Cookies, אין `localStorage`/`sessionStorage` של שאלות/נושאים, אין סקריפטי Analytics; רענון מאפס את מצב המשחק.
- **לוגים:** הסבר למשתמש איפה לראות ב-Vercel (Logs) שהלוג מכיל רק קוד שגיאה, שלב וזמן — בלי נושא או תוכן שאלה.

### 4.2 בדיקה ידנית של המשתמש (רשימה צעד אחר צעד שאמסור בסוף)
1. בטלפון: בית ← "בואו נשחק!" ← הקלדת נושא ← "שאלה חדשה" ← הודעת טעינה ← שאלה בעברית עם 4 תשובות.
2. בחירה בתשובה: משוב ירוק/אדום עם אייקון; התשובות ננעלות; בטעות — התשובה הנכונה מודגשת.
3. "שאלה חדשה" באותו נושא, ואז החלפת נושא.
4. מעבר לאודות וחזרה — השאלה והתשובה נשמרו.
5. סינון: נושא לא מתאים ← הודעה ידידותית לבחור נושא אחר, בלי שאלה.
6. תקלה והתאוששות: מצב טיסה ← "שאלה חדשה" ← הודעת "אין חיבור לאינטרנט" ← ביטול מצב טיסה ← "נסו שוב" עובד והנושא נשמר.
7. התקנת PWA: Chrome באנדרואיד/מחשב ("התקנת אפליקציה") או Safari ב-iPhone ("הוספה למסך הבית") ← פתיחה מהאייקון במסך מלא בשם "חכמולוגים".
8. טאבלט/מחשב: הפריסה לא נשברת והסרגל התחתון גלוי.

### 4.3 בדיקת העדכון האוטומטי מ-GitHub
- push נוסף ל-`main` (עם אישור המשתמש) — למשל שינוי ה-`engines` או סימון ההתקדמות ב-MILESTONES — ובדיקה ב-Vercel ← Deployments שנוצרה פריסה חדשה אוטומטית והאתר עודכן, בלי פקודת Deploy ידנית.

## 6. סיכונים ונקודות לתשומת לב
- **עלות:** ה-API ציבורי בלי Rate Limiting (החלטת המשתמש). להזכיר למשתמש להגדיר תקרת הוצאה (Usage limit) בחשבון OpenAI עצמו — זו הגדרה בחשבון שלו, לא בקוד.
- **Hobby — שימוש לא מסחרי בלבד** (ARCHITECTURE סיכון 3).
- **זמני תגובה:** פריסה ראשונה/"Cold start" עלולה להאט את השאלה הראשונה; ה-Timeouts (30/5 שניות בשרת, 40 בדפדפן, `maxDuration` 60) נשארים כפי שהם.
- **אזור (Region) של הפונקציה:** ברירת המחדל של Vercel (ארה"ב) מתאימה — קרובה לשרתי OpenAI. לא משנים.
- **מדיניות נתונים של OpenAI לילדים** (ARCHITECTURE 2.6): להזכיר למשתמש לעבור על תנאי השימוש לפני שיתוף רחב.

- כתובת האתר זמינה ב-HTTPS, ו-push ל-`main` מעדכן אותה אוטומטית.
